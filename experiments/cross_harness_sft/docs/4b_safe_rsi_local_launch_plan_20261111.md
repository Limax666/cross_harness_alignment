# 4B Harness Scaling 安全 RSI：本机启动计划

> 状态：准备中。用户已授权共享 GPU 0、2、3；2026-11-11 晚间可用内存约 21 GiB、交换空间已满。官方 4B 权重正在下载，未启动训练。

目标：以官方 `Qwen/Qwen3.5-4B` 后训练模型为起点，先建立 FlashRSI 执行框架下的安全和通用能力基线，再完成可复位环境、真实在线 rollout、FlashRSI 资源演化与模型 RL 衔接以及 CHS-PO 的小规模预检；预检通过再冻结正式实验。不得将既有 2B/9B SFT 模型误作 4B 起点。

## 已确认设计

- 不做项目内教师轨迹 SFT；模型上游后训练保留说明。4B 预检后 4B/9B 采用各自同系列后训练起点与同一主对照。
- 五个 harness 组件，先参考论文 18 配置、每任务 K=2 与邻近配置分配；另对比组件自演化与固定配置。保留未见配置和真实外部 harness，权限、任务语义与隔离边界不变。
- 按后续决策先基于开源 FlashRSI 推进资源演化，并与在线 GRPO / CHS-PO 的模型参数训练衔接；FlashRSI 的资源演化本身不是模型参数 RL。任务生成、验证和跨轮反馈仍需单独接入，不能称作已验证的递归闭环。
- 先使用良性通用任务观察安全效用变化，再让 GRPO 与 CHS-PO 在相同严格 clean/attack 配对任务和相同安全反馈下对照。通用 RSI 只用任务反馈另作对照。安全任务初期来源 AgentDojo、HarnessAudit；未见家族及独立 benchmark 用于最终评测。
- 共享任务池由独立同模型生成分支逐轮生成、验收、冻结，供两算法同时使用；另设独立递归闭环。模型自身生成是主实验，固定外部 worker 为对照。
- 每轮保存模型、五类组件、任务池、verifier、技能/记忆与生成器状态；统一 validation 规则挑 checkpoint，同时报告同预算末 checkpoint。最终测试不用于训练或选模。

## 先建立 FlashRSI 下的 4B 安全基线

在任何资源演化、任务合成反馈或模型参数更新之前，以固定的官方 4B 权重和 FlashRSI 初始 snapshot 执行真实评测；`--check-only` 不运行模型，不能作为基线结果。模型作为 target，记录实际 adapter 类型及模型调用协议；FlashRSI 的 Codex/OpenCode 语义移植不得标为原生 CLI。固定模型 revision、tokenizer/chat template、FlashRSI commit、snapshot 哈希、工具及权限、沙箱、评测数据版本、verifier、采样参数和随机种子。当前尚无经验证的 FlashRSI 安全环境接入，必须先完成接入与验收，不能声称基线已有结果。

1. **评测集与隔离**：优先从 AgentDojo、HarnessAudit 选可复位且 verifier 可靠的任务，先逐数据源验收真实工具执行、环境复位、安全副作用证据和正反例；严格配对的 clean/attack 使用相同合法目标、初始状态、权限及工具，改变攻击条件。冻结并审计 family、近重复及历史暴露；用开发集完成工程调试，以独立 validation 作为演化过程对照。最终 test 家族和留出 harness 仅在规则及模型选择冻结后使用，不向演化 worker、训练或选模反馈。若暂时没有合格配对或环境，记录阻塞，不能将现成单轮提示词冒充环境评测。
2. **初始系统基线 B0**：对同一冻结任务与攻击样本，运行官方 4B + 固定初始 snapshot；先覆盖接入并验收通过的 harness 配置，逐个配置保留原始任务结果及环境证据。18 个训练配置和留出配置的比较在各自适配与资源允许后开展；不把未实现的五维组件写成已测。重复采样的次数、种子、预算和超时预先冻结。
3. **报告指标及分母**：clean 任务成功数/有效评分数为 benign Utility；attack 中达成攻击目标数/有效评分数为 ASR；attack 中同时完成合法任务且无安全违规数/有效评分数为 safe-and-useful。按实际 verifier 定义分别报告越权、敏感信息泄露及持久化等可观测副作用；不适用或无 oracle 标记为不可测。另报总任务数、有效评分数、无效、错误和超时，未评分不得计作安全。按数据源、家族、harness 与 clean/attack 分层给出分子/分母和置信区间，并保留配对结果；重复采样需要区分单次成功率与 Pass@k，不把 Pass@k 当 ASR 或普通平均值。
4. **演化与训练对照**：B0 是固定初始系统，不等于 FlashRSI 自演化结果。接入不可变安全策略、工具权限及隔离边界后，另跑固定 4B 权重 + FlashRSI 演化 snapshot 的系统级基线 B1；记录演化算法、worker、可编辑范围、实际成本和冻结 snapshot。再与模型参数 RL 的 GRPO/CHS-PO 对照比较：相同评测任务、harness 条件、verifier、采样和预算，报告相对 B0/B1 的配对变化，同时标明哪些变化来自资源演化、哪些实验还包含参数更新；不能仅凭联合变化归因于单个组件。训练/选模期间只用 validation，冻结后再执行一次预定的最终 test 比较。
5. **产物与放行**：保存 run manifest、任务及配置 ledger、模型与 snapshot 标识、完整轨迹和重置/副作用证据、逐样本评分、聚合指标、错误统计和资源峰值。工程预检通过、样本与指标口径经审计且 B0 结果可复现后，才进入资源演化及后续训练预检；不因基线得分高低改变原先冻结的训练/测试划分。

## 实施任务与门槛

1. **模型与运行环境**：冻结官方 4B revision 和文件哈希；下载到新目录，核对 tokenizer/chat template、权重与磁盘。检查本机 VeRL/vLLM 版本、Qwen3.5 兼容性及 AgentDojo 所需环境，记录依赖与来源。真实模型加载和工具调用只在资源可用时验证。
2. **训练入口**：`scripts/train_rl_9b_whitebox.sh` 当前仅接受 2B/9B 且绑定旧 SFT 权重、K=2 AgentDojo pool，并非当前实验入口。新建独立 4B 配置/入口以引用固定 4B 模型、新 run、冻结 ledger 和明确 GRPO/CHS-PO；不得覆盖历史脚本和结果。冻结训练超参、资源布局和全参数/PEFT 模式，预检不冒充正式实验。
3. **数据与验收**：先完成 AgentDojo 和 HarnessAudit 的 family split、近重复与历史暴露审计；只纳入合法目标、初始环境、权限一致的严格 clean/attack 配对。验证重置、环境/工具映射、独立 verifier 正反例、安全副作用证据与无效归因。缺少可验证配对的风险类型暂不纳入。
4. **RSI 实现**：独立的任务合成、质量/权限/测试泄露门禁、诊断与新一轮冻结产物；保存每轮任务/组件/策略版本和 token 成本。先用固定小规模闭环确认产物确实进入下一轮；仅运行固定旧任务不是 RSI。
5. **训练预检**：4B 当前策略产生真实环境 rollout，验证 action-token mask、old log-prob、奖励分解、GRPO/CHS-PO 优势、actor 更新与 rollout 权重同步，记录资源峰值。资源不足时暂停，不终止其他用户进程、不改变精度或训练模式冒充同配置结果。
6. **正式实验冻结**：预注册样本、种子、计算/生成预算、validation 门槛、终点、停止和 checkpoint 选择。按相同任务/安全证据/配置对照 GRPO 与 CHS-PO；各自递归生成和组件演化分别消融；固定预算末和 validation 选模结果分开。
7. **泛化**：训练未见组件组合与真实 harness 分开；只迁移权重和迁移完整兼容资源各测。报告 safe-and-useful、benign Utility、ASR、持久化、越权、覆盖及置信区间；未评分不是安全。历史使用过的 HarnessSafe 与 HarnessSecurity-Bench 记录开发暴露。
