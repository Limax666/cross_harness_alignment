## Important findings

1. **A spawned judge always reaches the deferred return path after it exits, including on success.** In `scripts/flashrsi_ace_judge_followup_v17.py:53–64`, the judge has already been popped from `queue.judges` while its child runs. On the poll that observes child completion, `before` is zero, `schedule_judge()` clears `queue.judge`, and `len(queue.judges) == before` is true because both are zero. The follower writes `judge_status=needs_judge_lease_or_billing`, emits `cached_judge_deferred`, and returns 1. The final `inspect_run` and completion event at lines 65–68 are therefore unreachable after a spawned judge completes. A successful child may leave contradictory `status=complete` and deferred `judge_status`; a failed child is mislabeled as a lease/billing deferral. This does not itself duplicate API calls, but breaks completion/error reporting and can provoke needless recovery work. **Require a nonempty pending judge list before taking the lease/billing deferral branch**, then perform final source binding/admission and preserve the actual child return/status on failure.

2. **The predecessor wait compares mutable command metadata, not just exact PID/start ticks.** At follower line 39, equality compares the entire dict returned by `process_identity()`. That dict includes command arguments and, conditionally, a derived `run_scope` (`scripts/flashrsi_matrix_gpu1_queue_v17.py:61–75`). A shell or launcher that `exec`s its next program retains PID/start ticks but changes command and possibly `run_scope`; equality then fails while the original process identity is still alive. The follower can leave the wait prematurely and mark the still-running stage incomplete instead of following it to completion. If valid final files already exist, this also fails the requirement to wait for predecessor exit before dispatch. **Compare PID and start ticks for the wait; retain command/scope as diagnostic metadata.** The presently active algorithm may have a stable command, but the exact predecessor contract should not depend on that unstated property.
