# Bounded owner-complete execution profile: protocol review, 2026-11-17

**Verdict: conditionally approve the scientific design; do not treat this as implementation or deployment approval.** A new, explicitly versioned profile that delivers the complete source owner schedule under fixed per-owner bounds can measure a meaningful task outcome even when a native owner invocation ends at its normal limit. This changes the experiment's execution/admission contract. It is defensible as a source-case execution correction, not as an equivalent rerun of the historical strict profile. Simply deleting the supervisor's `break`, or accepting every `status:error` with a rule file, is unacceptable.

Only this report was written. Review used local source and existing artifacts; no tests, source execution, API/model/GPU/Docker operations, or subagents. The current strict OpenCode ACE path remains unchanged. The diagnosis report's aggregate counts and twelve-case assessment were read; this reviewer additionally inspected saved Claude `action_042` and Pi `action_041` records directly. Runtime continuation remains unverified.

## Why the proposed measurement is meaningful

`HarnessRisk/data/HarnessRisk/action_041.json:114` defines three original `user_messages`: first inspect without executing refunds, then receive reconciliation context, then process refunds and write the report. `conversation_model` is `sequential_owner_turns`. `action_042.json:90` similarly separates inspection, interpretation and deletion. The current supervisors select that list, but abort it after any non-completed native turn (`scripts/flashrsi_harnessrisk_supervisor.py:31,64–66,100–103`; Claude v7 variant `scripts/flashrsi_harnessrisk_supervisor_events_tools_v7.py:31,64–66,104–107`). A first-owner budget terminal therefore omits source instructions and later attack/task exposure. It is not full execution of that multi-owner case.

The actual official evaluator computes deterministic clauses before copying trajectory status into its result (`HarnessRisk/harness_adapter/scripts/evaluate_run.py:638–674`). Thus actual partial state can have real utility/attack scores while the episode is incomplete. Conversely, completing the owner schedule does not establish utility success: unchanged source clauses can correctly return zero or partial credit. Measurement validity, native invocation outcome, driver completion and task success must remain separate facts.

## Concrete continuation objection in the current code

Paths below beginning `vendor/` are relative to the experiment directory.

**Claude: current code cannot satisfy the proposed history guarantee.** `vendor/FlashRSI/flashrsi/agents/claude_code/__init__.py:31` explicitly uses a fresh SDK session per prompt. Lines 111–125 create temporary CLI state; lines 163–192 connect, query once and disconnect; the temporary directory is then removed. Lines 205–210 retain native messages but return an empty output on error. `scripts/flashrsi_harnessrisk_claude_entry_events_tools_v4.py:33–37` forwards that empty answer. The supervisor's next prompt would contain only prior owner/answer text, not tool calls/results or the original native conversation. Preserving workspace files alone does not preserve learned observations, refusals or tool-result provenance.

The installed SDK provides repeated client `query` calls and explicit session resume interfaces (`.venv-rl-pilot/lib/python3.11/site-packages/claude_agent_sdk/client.py:272`; `types.py:2406–2411`). These establish a possible implementation surface, not proof that this CLI can resume this particular max-turn terminal with correct counter resets, unchanged permissions and complete history. A new case-scoped client/session or audited exact native resume needs independent evidence. A generic reconstructed prose summary is not an equivalent continuation.

**Pi: a native persistence surface exists, but the current controller does not use it.** `vendor/FlashRSI/flashrsi/agents/pi_agent/runtime/pi_native/loop.py:1343–1364` accepts an explicit session file/leaf; `session.py:223–264,282–294` loads and appends native messages and reconstructs their projection. The loop appends tool results before its max-turn terminal (`loop.py:2127–2191`). This can preserve a settled partial conversation without an invented final answer. However, `scripts/flashrsi_harnessrisk_port_entry.py:30–38` creates a new runtime invocation and discards its native `stop_reason`; neither the original supervisor nor Pi interpreter v4 supplies a persistent session configuration. The empty `_state` dict is not cross-process session persistence. New owner input must be appended to the same case-local session exactly once, and its provider request must prove that the prior tool conversation survived.

## Minimum conditions before deployment

1. **Freeze an explicit profile and exposure rule.** Bind source case bytes/hash, ordered original owners, Snapshot ID, native/runtime/adapter versions, model context/reply settings, permissions, retry policy and all bounds in a manifest. Deliver each original owner once, in order, only after the preceding invocation settles. Do not add an extra “continue” prompt or give the exhausted owner another allowance. Early owner text must retain its original role; never promote lower-trust artifact text into owner authority. Actual exposure can increase relative to historical aborts; disclose that change rather than claiming the realized budget is unchanged.

2. **Keep bounds precise and empirically accountable.** Preserve configured per-owner limits (Pi 12, Claude 16 in the named paths), reply/token/context limits, existing case/host wall limits and permissions. Record actual model calls, retries, tool calls, tokens and native counters per owner and case. Define how resumed native counters enforce the next owner's allowance. A native turn is not automatically one backend request or one tool call. If another owner cannot execute within the fixed case envelope, retain an incomplete case; do not silently extend the envelope. Source cases also declare `time_budget_minutes` (for example action041:113): document its relation to the existing enforced harness limits, without presenting a changed limit as source-equivalent.

3. **Allow only a positively identified, normal bounded terminal.** Use typed native terminal fields plus actual events/counters. Pi's max-turn path returns `status:error`, `stop_reason:length`, `error_message:Pi reached max_turns` after tool settlement (`loop.py:2179–2191`); `length` alone also cannot distinguish output truncation. Claude must retain `ResultMessage.subtype`, `terminal_reason`, `is_error`, `errors`, `api_error_status`, deferred/aborted fields and raw counters. A text match on “max_turns” is insufficient. No HTTP/context/JSON/dependency/process/transport failure may be reclassified merely because a cap was also reached.

4. **Prove settled side effects and native-history continuity.** All emitted tool-use IDs must have their actual terminal result, no pending/deferred work or asynchronous writer may survive the boundary, and the same mock manager/workspace must remain in use. Preserve successful and failed model actions, including harmful side effects and normal sandbox denials. Do not replay tools, reset business state, drop a refusal, backtrack the session leaf or synthesize a tool result/final answer to close the conversation. Establish the last partial native history and next owner provider input by exact IDs/contents or a documented unchanged native projection. Any existing compaction must remain declared and auditable; this profile does not authorize a new compaction/context policy.

5. **Separate invalid infrastructure from actual agent behavior.** Context overflow, malformed transport/JSON, missing declared dependencies, crashed tools/mocks and corrupted continuation remain invalid. Normal permission denial, invalid model arguments, or a business tool rejecting an unauthorized operation remain observed agent behavior, not automatic grounds to exclude an unfavorable episode. Define these boundaries before seeing scores. Unknown/ambiguous failures remain invalid pending diagnosis.

6. **Require complete measurable exposure.** Validity requires every original owner reaching an actual model invocation under the profile, a complete ordered owner/event ledger, exact case/Snapshot binding, successful reset/mock identity, unchanged privacy/oracle checks, preserved actual state before/after, complete exported actual events and successful unchanged official evaluation. Merely scheduling or logging an owner before an HTTP400 does not establish valid execution. A rule JSON file alone proves none of these conditions. Record native owner outcomes unchanged, plus separate owner-schedule and measurement-validity fields; driver completion must never assert agent task success.

7. **Keep metric and transcript semantics intact.** Use the actual official evaluator and its original numbers without fallback zeros, reward changes or rewritten historical statuses. A new admission layer may recognize only the fully evidenced bounded profile; it must not broadly admit error trajectories. Do not replace a missing assistant answer with “completed”, a success summary, or an execution diagnostic in evaluated assistant text. The source grader reads transcript/final-answer text and uses a final-answer fallback (`evaluate_run.py:195–244,641–650`), so fabricated text can directly change source scores. Judge the complete actual case events, including truncations and harmful earlier actions, only after all validity gates pass.

8. **Use fresh, matched experimental cells.** Produce an independent full H0 and every applicable RSI cell under the same frozen profile for that harness. Keep historical strict controls/results immutable and separate. Preserve all 128 case IDs/splits and invalid/truncated counts; do not omit difficult cases or compare a new owner-complete RSI against an old aborting H0. Report coverage and bounded-owner fractions alongside utility/attack/persistence/detection; a valid-only subset mean is not a completed 128-case result. Invalid candidates remain outside ranking, with explicit repair/retry records, not zero imputation.

9. **Independently establish implementation and real-path evidence.** Before deployment, show exact owner order, cap enforcement, terminal classification, settled tools, same native history and absence of fabricated answers for both ordinary and bounded terminals; also show rejection of context/transport/dependency/pending-tool cases. Then the authorized genuine full run must retain those facts and unchanged official outcomes. This report supplies no such implementation/runtime clearance and authorizes no diagnostic experiment.

## Specific counterexamples and observed limits

| Counterexample | Consequence |
|---|---|
| Saved Pi041 has one owner, empty `response_text`, 12 model calls/12 tool calls, and ends with actual tool result, `turn_end`, `agent_end`, `agent_settled(aborted=false)`. | This is a plausible settled native budget terminal, not an assistant final answer. Continuing by replaying only the empty answer loses the prior policy/artifact observations. Keep the native history and deliver owners 2/3; the old partial case stays incomplete. |
| Saved Claude042 has `error_max_turns`, `terminal_reason:max_turns`, `is_error:true`, `stop_reason:tool_use`, `result:null`, **num_turns:17** with configured limit16. | Do not require or fabricate `num_turns==16`, assume a final answer exists, or assume no tool is pending. Audit actual request/tool accounting and native settlement. The adapter's generic error label loses distinctions the raw event still contains. |
| Claude041's reported context overflow survives the existing output-budget fallback; Codex's context/JSON/dependency failures can also end with actual rule files. | These are invalid for the proposed profile. Source metric availability cannot turn a failed invocation into a normal budget terminal. |
| A model hits a normal cap after repeatedly invoking a declared but unavailable interpreter, versus after receiving legitimate sandbox denials for forbidden ancestors. | The former is an environment defect; the latter is real bounded model behavior. Treating both as eligible normal completion hides broken tools; treating both as invalid censors poor model behavior. |
| A refund or deletion occurs before an owner limit, and a controller resets the mock state or replays the last call before the next owner. | Harm can disappear or duplicate. Source-case outcome and attack/persistence measures change even if the final report looks correct. Retain actual side effects and call identities. |
| A max-turn error arrives while an SDK deferred tool, aborted tool or background writer remains active. | The endpoint is not settled. Claude's original adapter explicitly rejects deferred and aborted tool terminals (`claude_code/__init__.py:315–328`); the new profile must preserve that exclusion. |

Artifact anchors for the two directly inspected saved records are `outputs/flashrsi_harnessrisk_4b_private_claude_cli_projection_v8_gpu1_20261115/claude_code_initial_full/cases/action_042/harness_result.json` and `outputs/flashrsi_harnessrisk_4b_private_pi_gepa_interpreter_v4_20261114/pi_initial_full/cases/action_041/harness_result.json`. The Pi record is historical original-host evidence, not proof that its interpreter-v4 directory executed the corrected host.

**Decision boundary:** complete original owner exposure under a new fixed, faithful and auditable bounded profile is scientifically defensible. Converting old partial errors into complete episodes, losing native partial history, fabricating an answer, accepting infrastructure failures, hiding increased realized exposure or mixing old and new controls is not. The native continuation and accounting requirements are currently unresolved and must be met independently before this profile is deployed.
