## P-I1 — Important: mock-request work is not covered by the settlement receipt

`scripts/flashrsi_harnessrisk_pi_native_owner_supervisor_v6.py:155–188` advances an owner after child exit and `process_receipt`. The guard in `scripts/flashrsi_pi_owner_profile_v6.py:284–298` explicitly permits the live mock manager and all its descendants, then returns `settled=True`. There is no corresponding trusted direct-mock request counter, response barrier or service-work receipt before the next owner or source export at supervisor lines208–216.

Those permitted services perform work on threads: `HarnessRisk/services/common/mock_server.py:315–317` uses `ThreadingHTTPServer`; lines275–280 read and dispatch each request. The selected process backend starts these service processes under the manager (`HarnessRisk/harness_adapter/harness_adapter.py:1090–1106,1129–1145`). The mock gateway may also synchronously forward to another threaded service (`HarnessRisk/services/mock_gateway/app.py:199–225`). The target is allowed to connect to this gateway (supervisor lines123–126). A tool can send a mock request and exit without waiting for the response; absence of target processes does not imply that a permitted server thread has finished processing or persisting that request. The next owner/export can therefore race mock mutations while the current receipt says settled. Model-provider request receipts do not observe this separate port.

Required repair: establish and archive a trusted barrier for every target-originated mock request and any forwarded service work, or fail closed when that work cannot be proved settled. Keep the original service behavior, permissions and budgets. A process census alone must not authorize continuation. A pure regression should cover a pending mock request despite an otherwise permitted manager/service process tree; this review did not execute such a scenario.

## P-I2 — Important: the untrusted session reader can block before checking its file type

`scripts/flashrsi_pi_owner_profile_v6.py:109` opens the actor-writable final session path with `O_RDONLY | O_NOFOLLOW`; the regular-file test happens only at line110. Opening a FIFO for reading blocks before that test. The current confinement does not forbid creating a FIFO in writable scratch: `scripts/flashrsi_native_seccomp.py` does not deny `mknod`/`mknodat`, and `scripts/flashrsi_landlock.py` grants its writable-root rights, including FIFO creation. Symlink protection does not address this case.

Both the normal archival read (supervisor line161) and its exception archival read (lines193–195) use this helper. A replaced session FIFO can hang the trusted supervisor until the outer case watchdog, preventing the intended immediate typed rejection and spending the remaining case envelope in an archive read. This is a code-path defect identified statically, not an observed live occurrence.

Required repair: open the final descriptor nonblocking, preserve descriptor-relative `O_NOFOLLOW`, verify regular-file type before reading, and enforce a bounded archive size/read policy. Add an isolated FIFO/nonregular-file regression with a bounded parent-side deadline; retain the existing symlink checks. No native agent or model run is needed to verify the reader.

## P-I3 — Important: independent case admission does not close the source/mock/host identity chain

`scripts/flashrsi_pi_owner_profile_v6.py:375–382` accepts a single matching case ID and finite official metrics without requiring the official run's `status` to be `completed`. The original evaluator computes numeric metrics and copies the exported trajectory status independently (`HarnessRisk/harness_adapter/scripts/evaluate_run.py:648–661`), so finite metrics do not establish source measurement completion.

The same admission function never binds `adapter_metadata.json`'s actual mock reset (`mock_start.reset.ok`, reset case identity and service reset results) to the requested case, nor checks the exported trajectory's case/status/result/Snapshot identity. Those source fields exist: the adapter records reset results at `harness_adapter.py:1113–1121`, writes them to adapter metadata at lines1728–1738, and exports case/status/mock-start/result at lines1471–1494. The host check at profile lines384–387 likewise omits the host receipt's available case ID and Snapshot ID. Initial, benchmark and reference admission all call this same function, so they do not independently reject these inconsistent artifacts. A correctly executed fresh supervisor normally intends to produce matching artifacts; that intent is insufficient for the promised independent admission.

Required repair: validate the completed official-grade status, actual successful case-matched mock reset/service results, source-export identity and measurement status, and matching host case/Snapshot identity against trusted caller inputs. Preserve the explicit owner-schedule semantics and raw native max-turn errors; this is no request to rewrite native statuses or impute scores. Add a real-shaped valid admission fixture and individual corrupted status/reset/export/host variants. The current scoped tests exercise rejection of a bare legacy result, but not a complete valid case with these fields independently corrupted.
